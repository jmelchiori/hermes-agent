# Profile gateway runtime layout

Status: active for generated profile gateways as of 2026-05-27.

## Decision

Generated profile gateways use the same Hermes home shape as Hermes WebUI sessions:

```text
HERMES_HOME=/home/hermeswebui/.hermes/profiles/<profile>
HOME=/home/hermeswebui/.hermes/profiles/<profile>/home
HERMES_CONFIG_PATH=/home/hermeswebui/.hermes/profiles/<profile>/config.yaml
PYTHONPATH=/workspace/hermes-agent-private
```

The shared host directory is still `./hermes-home`, but inside profile gateway containers it is mounted at:

```text
/home/hermeswebui/.hermes
```

`/opt/data` remains mounted as a temporary compatibility alias for old scripts, docs, or skill/config references that have not yet been retired. New generated profile-gateway runtime paths should use `/home/hermeswebui/.hermes`, not `/opt/data`.

## Why

Hermes WebUI imports `hermes-agent` directly and cannot target a remote runtime. Running profile gateways with a different filesystem/env contract created persistent drift between WebUI and gateway sessions even when both saw the same host volume.

The fix is to make every direct Hermes runtime for a profile use the WebUI-compatible profile layout instead of trying to reconcile two runtime worlds.

## Generator

Profile gateway services are generated by:

```bash
python3 scripts/generate_profile_gateway_compose.py
```

The generated services set:

```yaml
HERMES_HOME: /home/hermeswebui/.hermes/profiles/<profile>
HOME: /home/hermeswebui/.hermes/profiles/<profile>/home
HERMES_CONFIG_PATH: /home/hermeswebui/.hermes/profiles/<profile>/config.yaml
XDG_STATE_HOME: /home/hermeswebui/.hermes/profiles/<profile>/home/.local/state
PYTHONPATH: /workspace/hermes-agent-private
volumes:
  - ./hermes-home:/home/hermeswebui/.hermes
  - ./hermes-home:/opt/data   # temporary compatibility alias
  - ./workspace:/workspace
```

## Verification

For each profile gateway:

```bash
docker exec hermes-webui-stack-gateway-<profile> sh -c '
  printf "HERMES_HOME=%s\nHOME=%s\nHERMES_CONFIG_PATH=%s\nPYTHONPATH=%s\n" \
    "$HERMES_HOME" "$HOME" "$HERMES_CONFIG_PATH" "${PYTHONPATH:-}"
  /opt/hermes/.venv/bin/python - <<"PY"
from hermes_constants import get_hermes_home
print("get_hermes_home=", get_hermes_home())
PY
'
```

Health probes from the shared Tailscale namespace:

```bash
docker exec hermes-webui-stack-tailscale wget -q -T 5 -O- http://127.0.0.1:<port>/health
```

## Root/default gateway exception

The root/default `hermes-gateway` service was not migrated in this pass. A test migration exposed a separate pre-existing issue: the root gateway selects the infrastructure profile config and collides with the infrastructure API port (`8647`). The root gateway was rolled back to its pre-migration `/opt/data` layout until that separate default-profile/config-selection issue is resolved.

Do not infer profile-gateway failure from the root gateway's `8642` health state; verify profile gateways on ports `8643`-`8649` independently.

## Rollback

Migration backups are written under:

```text
state/runtime-layout-migration/backups/<timestamp>/
```

To roll back generated profile gateways, restore `scripts/generate_profile_gateway_compose.py`, regenerate `docker-compose.override.yml`, then recreate only gateway services. Do not recreate WebUI, Tailscale, Hindsight, Helm, or AgentHub API as part of this rollback unless separately required.
